# OperationsIQ Alignment

## Why this note exists

[OperationsIQ](https://github.com/slavatrofimov/OperationsIQ) is a Fabric App for operational
intelligence (signal exploration, forecasting, pattern discovery, anomaly detection, and
investigations). It was reviewed as a source of ideas for making this demo feel more like a
complete, integrated Fabric solution. This note records what was adopted, what was deferred, and
why - so the decision isn't lost the next time someone asks "should we add X from OperationsIQ".

## What OperationsIQ actually is

OperationsIQ is a full custom Fabric App (Rayfin control plane): a React/TypeScript SPA, a
GraphQL/SQL database for job and label metadata, an asynchronous Spark compute plane running
Matrix Profile motif/discord mining (MOMP/DAMP), a KQL/Eventhouse result store, a guided
wizard UX, and a Foundry-based "Operations Advisor" agent. Its own design spec is explicit that
most of this is a design-and-spec-sign-off phase, not shipped code - it represents weeks of
dedicated engineering on a separate product surface.

## Decision: borrow concepts, not the app

Porting OperationsIQ's Fabric App wholesale into this repository would mean building a second
product, not augmenting this one. This demo's value proposition is *causal data integrity ->
governed ontology -> natural-language investigation over Fabric IQ*, not a bespoke analytics SPA.
Two ideas were adopted because they are Fabric-native, low-cost, and directly strengthen the
existing incident-bridge model. Everything else was deferred.

| OperationsIQ concept | Status | Where |
|---|---|---|
| Investigation artifact (saved finding + evidence trail) | **Adopted** | `raw_investigations` (generated by `generate_investigations` in `src/data_generator/generate.py`), `data_contracts/bronze_tables.yml`, `semantic_model/semantic_model.yml` (`Investigation` entity), `semantic_model/tmdl/measures.tmdl` |
| Activator closed-loop (discovered condition -> always-on rule -> notify/act) | **Designed, with ready-to-import artifacts; not deployed** | See "Closing the loop" below and `deployment/activator/` (KQL query + `ReflexEntities.template.json`). Deploying it live still requires a real Fabric workspace/tenant, which this repo does not have credentials for. |
| Fabric App (Rayfin) custom SPA, guided wizard, labeling UI | Deferred | Multi-week build, requires Fabric Apps (preview) tenant enablement; wrong tool for a data/ontology demo. |
| Spark Matrix Profile motif/discord mining (MOMP/DAMP) | Deferred | Real value for shape-based anomaly detection over dense telemetry, but it is its own analytical engine and a multi-phase build (OperationsIQ's own roadmap is P0-P9). Revisit only if a future phase needs pattern-of-shape detection beyond the current threshold-based severity bands. |
| Operations Advisor (Foundry agent grounded in operational context) | Deferred | Directly relevant conceptually - an agent grounded in the asset/incident/investigation graph - but is its own project. See `foundry-hosted-agents` and `foundry-iq` skills if this is picked up later. |

## What was implemented

### Investigation artifact

`generate_investigations()` creates one `Investigation` row per High severity incident,
summarizing the incident's confirmed impact using numbers pulled from the bridge tables rather
than free text:

- `affected_asset_count` from `raw_bridge_incident_asset`
- `affected_service_count` from `raw_bridge_incident_service`
- `related_case_count` from `raw_support_cases`
- `sla_exposure_amount` from `raw_sla_exposure`

This mirrors OperationsIQ's "preserve the evidence" step (turning a chart/finding into a
reusable, linkable record) without needing a labeling UI - the record already carries the deep
link (`incident_id`) back to the underlying bridge data. `validate_scenario.py` checks that the
primary incident's investigation counts match the bridge tables exactly.

### Closing the loop: Activator (design, not deployed)

OperationsIQ's differentiator is that a discovered condition can be promoted into a Fabric
Activator rule that keeps watching after the analysis session ends. The equivalent here:

1. Bind an Activator rule to `raw_bridge_incident_asset` (or the Eventhouse table populated by
   `stream_simulator.py`, once wired to a real Eventstream).
2. Trigger condition: `packet_loss_pct > 5` (Critical threshold, see `generate_telemetry_events`)
   on any asset in a High severity incident's bridge.
3. Action: notify the NOC channel/Teams and optionally open a work order.

This is intentionally left undeployed rather than a live resource: this repository has no live
Fabric workspace or tenant credentials, and `deployment/Create-FabricAssets.ps1` only creates
placeholder items today (see `docs/05-fabric-implementation-plan.md`). What *is* provided is a
ready-to-import starting point in `deployment/activator/`:

- `network_degradation_query.kql` - the `kqlSource-v1` data source query, scoped to
  `packet_loss_pct` readings on assets bridged to a High severity incident.
- `ReflexEntities.template.json` - the full Activator entity graph (Container -> KQL Source ->
  SourceEvent -> `EventTrigger` Rule -> Teams action), using a transition-based
  `NumberBecomes`/`BecomesGreaterThan` detector on `metric_value > 5` so the alert fires once per
  crossing instead of on every polling interval.

When a real workspace is available: regenerate the template's placeholder GUIDs, fill in the
workspace/KQL database IDs, add the `network_incident_bridge` lookup table it depends on (see
`deployment/activator/README.md`), and import via `updateDefinition` on the
`{prefix}_degradation_alert` Activator item that `Create-FabricAssets.ps1` creates.

## Non-goals

- No React/TypeScript frontend was added. The demo's UI surface remains Power BI + Fabric IQ.
- No Spark motif/discord mining was added. Telemetry severity is still threshold-based
  (Normal/Warning/Critical bands), not shape-based.
- No Foundry agent was added. If pursued later, ground it in `Investigation`, `Incident`,
  `Bridge Incident Asset`, and `Bridge Incident Service` the same way Operations Advisor is
  grounded in OperationsIQ's asset hierarchy and prior investigations.
